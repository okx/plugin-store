| `buildRequestWithdraw` | Tx-approve | ezETH `allowance`, `balanceOf` | `validatePositiveAmount`, `validateEvmAddress` × 2 | yes (ezETH → WithdrawQueue) | filled | `WithdrawQueue.withdraw(amount, assetOut)` |
| `buildClaimWithdraw` | Tx-single | none (best-effort: caller checks via `listWithdrawRequests` first) | `validatePositiveIntegerString`, `validateEvmAddress` | no | filled | `WithdrawQueue.claim(index, user)` |

> **Class legend:**
> - `Tx-approve` = transaction tool that needs ERC-20 approve (multi-step skeleton)
> - `Tx-single`  = transaction tool, no approve required (single pending_sign)
> - `Read`       = read-only (returns ok | error)

## Validation checklist — every transaction tool MUST

- [x] Call `resolveChain(params.chain)` first; return UNSUPPORTED_CHAIN on bad input
- [x] Validate every address with `validateEvmAddress`
- [x] Validate amounts with `validatePositiveAmount`
- [x] Validate integer-string params (withdrawRequestIndex) with `validatePositiveIntegerString`
- [x] For multi-step flows: read allowance via `erc20.allowance(..., chain)` and emit approve pending_sign if insufficient
- [x] For multi-step flows: include "After this transaction lands, re-invoke <tool> with the same params" in the approve description
- [x] Return `PendingSign | ToolError` typed return
- [x] Use `lc()` on every address before passing to viem
- [x] Use `encodeFunctionData` from viem (no manual selector concatenation)

## Read-only tool checklist

- [x] Validate required params (return ToolError for missing/invalid input)
- [x] For `getEzethRate`, document the dual source (`chain` default vs `api` opt-in)
- [x] For `listWithdrawRequests`, return both `indices` and `outstanding` count so the agent can short-circuit empty cases

## API quirks / protocol-specific checklist (v0.1.0 — Form C decisions)

Renzo is built directly against verified contracts (no aggregator), so the API-quirks
matrix from the scaffold template is sparse. Decisions made for v0.1.0:

| Decision | Choice | Why |
|---|---|---|
| Decimals for ezETH / ETH | hard-coded `18` | Both are 18-decimal canonical tokens; no caller input needed |
| `assetOut` for withdrawals | user-provided, validated as EVM address | The WithdrawQueue accepts an allowlist of `_assetOut` values; v0.1.0 does not enforce the allowlist client-side — best to call `previewWithdraw` first |
| ETH-only deposits | `buildDepositEth` only — ERC-20 collateral `deposit(token, amount)` deferred to v0.2.0 | Adds approval flow + per-LST allowlist validation; out-of-scope for v0.1.0 |
| L2 deposits | not supported — `chains: [ethereum]` only | L2 mints flow through `xRenzoDeposit` (different ABI); v0.2.0 candidate |
| Instant withdrawals | not supported — `InstantWithdrawer` contract not yet wired | v0.2.0 candidate; standard `WithdrawQueue.withdraw` only in v0.1.0 |
| pzETH (Symbiotic), ezREZ, ezEIGEN, ezBTC, ezSOL | not supported | Separate vaults, separate Vault contracts; one-by-one expansion in later versions |

## Error code catalog — protocol-specific codes

Standard codes already provided (see SKILL.md). Renzo-specific:

| Code | Meaning |
|---|---|
| `RENZO_API_ERROR` | `app.renzoprotocol.com/api` call failed or returned non-200 |
| `NO_PENDING_REQUESTS` | (Reserved — not yet emitted) For agent UX when user calls claim/list with zero outstanding |
