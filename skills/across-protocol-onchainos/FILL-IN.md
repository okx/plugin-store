## Per-tool matrix

| Tool | Class | Across endpoint | Reads needed | Approve? | Notes |
|------|-------|-----------------|--------------|----------|-------|
| `listSupportedChains` | Read | `GET /swap/chains` | none | n/a | Returns the live origin + destination chain list. |
| `getQuote` | Read | `GET /swap/approval` (preview) | none | n/a | Returns expected fill amount + estimated fill time. No state mutation. |
| `getDepositStatus` | Read | `GET /deposit/status` | none | n/a | Polls fill status for a previously-broadcast deposit. |
| `buildSwap` | Tx-approve (multi-step) | `GET /swap/approval` | validate input/output addresses, amount, decimals; resolve origin + destination chains | yes (when `approvalTxns[]` is non-empty in the response) | Emits Step 1 of 2 (approve) if the Across API response includes `approvalTxns`; re-invoke with same params after the approve lands to receive Step 2 (the swap tx). |

## Validation invariants (all met by current `index.ts`)

- [x] Every address validated with `validateEvmAddress` before passing to `lc()` / API
- [x] Amount validated with `validatePositiveAmount`
- [x] `validateDecimals(params.amountDecimals, 'amountDecimals')` runs before any `parseUnits(amount, amountDecimals)` call (A7 invariant)
- [x] `lc()` applied to every address before passing to the Across API
- [x] Returns `PendingSign | ToolError` — never throws
- [x] Multi-step `buildSwap` includes `step_info: {current, total, name}` for clean UX
- [x] Description in the `pending_sign` envelope clearly states "Step 1 of N: Approve... After this lands, re-invoke buildSwap with the same params to receive the next transaction." for the approval branch
- [x] No local-signing residue (A4): every signing path routes through `next_action.tool = 'onchainos wallet contract-call'`

## API quirks checklist (v1.14 — P1-16)

| Quirk | Default | Why |
|---|---|---|
| `slippage` | `'auto'` (lets Across pick a sensible default per route) | User can override with a numeric value (basis points) |
| `tradeType` | `'exactInput'` | "I send X" semantics — most intuitive for end users |
| `recipient` | `walletAddress` (sender = receiver default) | Caller can override for sending to a different destination address |
| `appFee` / `appFeeRecipient` | omitted | Integrator fee collection — opt in by setting these explicitly |
