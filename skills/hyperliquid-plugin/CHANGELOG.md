# Hyperliquid Plugin Changelog

### v0.6.2 (2026-09-03) — order sizing priced at the order's price, JSON error contract

- **fix**: $10 minimum notional (and `notional_usd`) now charged against the order's own price — limit price for limit orders, mid for market. Verified live: 0.11 HYPE @ limit 99 ($10.89 / $9.00 at mid) is accepted, so the old mid-based sizing over-sized limit orders (0.13 → $12.87 of real value).
- **fix**: `get-gas` returned a bare stderr `Error:` with empty stdout and exit 1; now returns the standard `{"ok":false,"error_code":...}` JSON on stdout.
- **fix**: `order-batch` `type` defaulted to `"limit"` (inconsistent with single `order`); now inferred from `price`. `size`/`price` accept numbers as well as strings.
- **fix**: `evm-send` submitted step 2 (spot -> HyperEVM) even when step 1 (perp -> spot) had **reverted** — the new `Result<bool, String>` return of `wait_tx_mined` was matched on `Err` only, so `Ok(false)` fell through silently. A reverted step 1 now aborts with `STEP1_REVERTED` before step 2 is sent.
- **fix**: `get-gas` printed a reverted relay deposit as "timed out", discarded the result, and returned a hard-coded `"on_chain_status": "0x1"` — a failed deposit was indistinguishable from a successful one. It now reports `DEPOSIT_REVERTED` on revert.
- **fix**: `evm-send` and `get-gas` carry the observed receipt status (`0x1` / `0x0` / `{"unconfirmed": reason}`) instead of a hard-coded `"0x1"`, matching `deposit`.
- **tests**: +9 (5 sizing unit tests, 4 batch-input unit tests).


### v0.6.1 (2026-09-03) — unified-account margin gate, honest tx confirmation

- **fix**: `order` blocked fully funded orders on a unified account (gate read only `clearinghouseState.withdrawable`, which is `0.0` there) and suggested a `transfer --direction spot-to-perp` that HL rejects as "Action disabled when unified account is active". Gate now reads `userAbstraction` and counts spot USDC as margin under `unified` / `portfolio`.
- **fix**: switched `ARBITRUM_RPC` off `arbitrum-one-rpc.publicnode.com` (refuses `eth_getTransactionReceipt` with `-32602`) to `https://arb1.arbitrum.io/rpc`.
- **fix**: `wait_tx_mined` now returns `Result<bool, String>` and surfaces the real failure instead of a bare `false`; bails out on endpoint refusal rather than retrying to the deadline.
- **fix**: `deposit`'s `on_chain_status` was a hardcoded `"0x1"`; it now reports the observed status.
- **docs**: `deposit` — $5 bridge minimum and unified-account fund destination.


### v0.6.0 (2026-07-29) — Autotrade (copy-trading) authorization gate

- **feat**: `order` / `close` accept an optional `--autotrade-job <jobId>`. When present, the binary calls `onchainos agent autotrade-grant-check --job-id <id> --venue hyperliquid --action <buy|sell> --amount <quote-notional> --format json` **before any signing or submission** — including before the separate leverage-update action that `--leverage` triggers. The order proceeds only when stdout parses as JSON with `ok:true`; the subcommand exits 0 even on denial, so the verdict is read from the `ok` field, never the exit status. Every other outcome — `ok:false` (reason passed through verbatim), non-zero exit, unparseable stdout, timeout (10s, child killed), unlaunchable binary, or an onchainos too old to know the subcommand — fail-closes with `{ok:false, error_code:"AUTOTRADE_GRANT_DENIED"}`. The plugin never reads the authorization grant itself; grant, per-trade limit and subscription state all live on the onchainos side, and the error output never carries grant-file contents or paths (the subprocess stderr is deliberately not echoed).
- **feat**: the submitted `--amount` is the **quote-currency notional** the order can consume at most — exact fixed-point size times the highest of mid / worst-fill / limit price, rounded up to the cent. The buyer's written cap is denominated in quote stablecoin (`onchainos agent autotrade-consent-set --cap`), so a base-unit size would be compared against it directly and clear any cap regardless of the order's real value. Taking the highest candidate price keeps the figure an upper bound for longs and shorts, market and limit alike; when no price is available the order is refused rather than submitted with a figure that would pass. `--action` is the order side for `order` and the **closing** direction for `close` (closing a long → `sell`).
- **feat**: jobId validation at command entry — charset `[A-Za-z0-9_-]`, length 1..=128 (0x-prefixed hex passes naturally). Invalid values are rejected with `{ok:false, error_code:"INVALID_INPUT"}` before any network request or subprocess.
- **fix**: the minimum-notional auto-adjust is disabled on the autotrade path. Interactively an order below the $10 exchange minimum is still raised to the smallest size that clears it; with `--autotrade-job` the order is refused with `ORDER_BELOW_MIN_NOTIONAL` instead, because raising the size would execute more than the grant authorized.
- **fix**: autotrade execution-card parameters are immutable inside the binary. Off-grid sizes and prices are rejected instead of rounded, invalid slippage values fail before network/signing, and `onlyIsolated` markets reject a leveraged card that omitted `--isolated` instead of silently adding the flag. Autotrade errors consistently route to the card's failure branch without suggesting funding, parameter changes, or retries.
- **feat**: `--autotrade-job` + `--dry-run` skips the grant check (nothing is signed or submitted) and marks the preview `autotradeGrantCheck: "skipped (dry-run)"`. Authorized successful orders carry `autotradeJob: <jobId>` in the result for audit correlation. A preview without `--confirm` never consumes an authorization.
- **refactor**: every onchainos invocation in `src/onchainos.rs` now resolves the executable through one entry point (`HYPERLIQUID_ONCHAINOS_BIN` override → `~/.local/bin/onchainos` → PATH).
- **docs**: SKILL.md — new "Autotrade (copy-trading) exception" section after the Live Trading Confirmation Protocol (three verifiable conditions + two hard prohibitions: never modify execution-card parameters, never retry or re-route a rejected order); `order` / `close` each document `--autotrade-job`; the minimum-notional note records the autotrade difference.
- **compat**: no breaking changes. Without `--autotrade-job`, behaviour is unchanged from 0.5.0 — the grant check is never invoked and the existing test suite passes without modification. Interactive usage keeps the unweakened confirmation protocol. The gate is safe to ship ahead of the onchainos side: `agent autotrade-grant-check` exists as of onchainos 4.4.1 but its `--venue` enum is `dex | defi | polymarket`, so `--venue hyperliquid` currently returns `{"ok":false,"reason":"invalid venue"}` and every `--autotrade-job` call fail-closes until the venue is added upstream. Interactive users are unaffected.
- **tests**: `tests/autotrade_grant.rs` spawns the compiled binary against a mock Hyperliquid API and the `mock_onchainos.sh` fixture (grant modes: ok / deny / hang / bad-JSON / crash / old-CLI), asserting on the recorded onchainos invocations so "nothing was signed" is verified rather than assumed. `tests/endpoint_overrides.rs` pins that test-injection hooks remain disabled unless explicit test mode is active. The fixed-point authorization math also has direct boundary coverage.
