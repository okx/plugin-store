## Form classification

**Form B-REST equivalent.** The source `morpho-cli` is a markdown-only skill
documenting `npx @morpho-org/cli@latest`. The CLI itself plays the role of a
REST backend — every `prepare-*` call returns unsigned transactions in JSON,
and there is no local signing anywhere in the source. `runtime.ts` shells out
to the CLI in real mode; mock mode uses canned response fixtures.

## Phase order

1. **Static review** — read SKILL.md from a new-user perspective. Adjust Quickstart / Onboarding wording. Use `explore-plugin` skill for guided review.
2. **B-mock fill-in** — already complete. `runtime.ts` ships with mock fixtures for every Morpho CLI command. Verify each tool runs end-to-end via `tsx cli.ts <tool> '<json>'`.
3. **B-real wiring** — already in place. Real mode invokes `npx @morpho-org/cli@latest <command>` and parses the JSON response. The CLI does its own decimal handling, allowance checking, simulation, and transaction packing, so there is no SDK signature smoke to run.
4. **Regression sweep** — use `test-skill` skill to run Phases −1/0/1/2/3/4/5/6.
5. **Live test (OPTIONAL)** — only if a funded onchainos wallet is available + user opts in.

## Validation checklist — every transaction tool MUST

- [x] Call `resolveChain(params.chain)` first; return UNSUPPORTED_CHAIN on bad input
- [x] Validate every address with `validateEvmAddress` and every market id with `validate32ByteHash`
- [x] Validate amounts with `validatePositiveAmount` (accepts `max` for withdraw/repay variants)
- [x] For multi-step flows: skill emits the first remaining tx; agent re-invokes after each lands
- [x] Approve description includes the "After this transaction lands, re-invoke `<tool>` with the same params" hint
- [x] Return `PendingSign | ToolError` typed return
- [x] Use `lc()` on every address before passing to the Morpho CLI

## API quirks checklist — Morpho specifics

| Quirk | Notes |
|---|---|
| Chain naming | CLI accepts slugs (`base`), not chain IDs (`8453`). The wrapper validates and passes slugs through. |
| `--amount` semantics | Human-readable (`1000` for $1000 USDC), not raw units (`1000000000`). The wrapper passes the string through verbatim; CLI does the decimal math. |
| `--borrow-amount` flag | The borrow tool uses `--borrow-amount`, not `--amount`. Wrapped via `borrowAmount` field on `prepareBorrow`. |
| `max` keyword | `prepare-withdraw` / `prepare-repay` / `prepare-withdraw-collateral` accept `'max'` as amount; the validator allows it. |
| `--no-simulate` | Boolean flag in CLI. Wrapper exposes `noSimulate: true`. Default keeps simulation on. |
| `simulationOk` vs `allSucceeded` | `prepare-*` uses `simulationOk`; `simulate-transactions` uses `allSucceeded`. The wrapper checks `simulationOk` on prepares. |
| Partial withdraw | `prepare-withdraw --amount max` may return less than the full balance with a `warnings[]` entry. The wrapper surfaces the warning in the `description` field of `pending_sign` (does NOT block). |
| Vault v1 vs v2 | The same CLI works for both. v2 vaults use `kind: "adapter"` in allocations; surface as-is. |
